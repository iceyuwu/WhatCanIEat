# 基于SpringBoot+Vue的菜谱系统

## 摘要

在现代生活中，互联网浪潮和移动终端不断深入现代生活，人们特别是年轻人群体在日常生活中对饮食健康、快捷制作食品和便捷获取菜谱信息的需求日益增长，传统的纸质菜谱和零散网络信息已经难以满足用户对菜谱查询、收藏、分享和推荐等方面的需求。基于此，本文设计并实现了一套基于 SpringBoot + Vue 的菜谱系统。系统采用前后端分离架构，前端基于 Vue 框架进行页面构建，后端采用 SpringBoot 框架提供业务逻辑支持，数据库使用 MySQL 进行数据存储，并结合 MyBatis 实现数据访问层的高效开发。

本系统主要实现了用户注册登录、菜谱发布与管理、菜谱检索与展示、用户收藏、评论互动以及随机推荐等功能。系统界面简洁美观能够满足用户在菜谱浏览、学习烹饪和个性化管理等方面的需求。通过系统测试，验证了各模块功能的正确性。实践表明，该系统具有良好的可扩展性和实用价值，为基于 Web 的生活服务类系统开发提供了一定的参考。

## 概述

随着生活水平的提高以及健康饮食理念的普及，越来越多的人开始重视饮食质量与营养搭配。相比外卖和餐饮消费，亲自烹饪不仅经济实惠，还饱含了自己动手的乐趣和亲情，最是一件能使一家其乐融融的趣事，因此逐渐成为许多家庭的日常选择。可是，很多人由于没有特别练习过烹饪技术，或是缺少时间亲自下厨，又或是巧妇难为无米之炊，很难找到细致靠谱的菜谱，只是想享用卫生美味的家常菜时被现实处处掣肘。在互联网发达的当今社会，人们自然会转向网络来寻找能够解决自己需求的答案。但由于菜谱信息往往分散在各类网站、视频平台和社交媒体中，并且不同平台的内容质量参差不齐，没有统一的搜寻方法，在寻找合适的菜谱时往往需要花费很多宝贵的时间进行筛选。传统菜谱平台通常以简单分类或关键词检索为主，难以根据人们的要求进行个性化推荐。所以，构建能够支持个性化检索与推荐的菜谱系统，能够有效改善使用体验和提高菜谱获取效率。在菜谱展示和检索之外，随着互联网社区的发展，越来越多来自各地的厨艺爱好者能够分享自己的烹饪经验和特色菜谱，让自己的家庭味道也能令另一家人赞不绝口，让远方的游子也能通过制作熟悉的菜品一窥家中的烟火。通过建立一个菜谱分享平台，许多特色菜谱得以走出高山，跃出大海，凭借美味在网络上留下自己的一席之地。

本课题基于 Web 开发技术，采用 SpringBoot + Vue 架构，构建一套集菜谱管理、用户互动和个性化推荐于一体的综合性菜谱系统。系统通过前后端分离的方式，提高了系统的开发效率和维护性，使前端界面和后端业务逻辑解耦，便于后期扩展和升级。

本系统旨在实现一个性化菜谱分享与检索平台，为用户提供一个集菜谱浏览、检索、分享与和谐交流于一体的综合性应用平台。在功能上，本系统将为用户提供检索菜谱，浏览菜谱，分享菜谱和收藏。菜谱的。基本功能。并且围绕菜谱系统提供一系列趣味性的功能。在系统设计上，项目采用前后端分离的B/S架构模式，前端界面负责用户浏览与交互，后端系统负责业务逻辑和数据处理。目标是打造一个视觉效果简洁高效清晰，系统整体稳定性强，能够承载一定的并发量的中小型网站项目。

#### 概述

#### B/S架构

B/S架构，即浏览器/服务器架构，是一种在当今非常常见的系统架构模式。在B/S架构中用户需要通过浏览器来访问网站，而相关的业务逻辑、数据操作都在服务器端完成。用户通过浏览器发送请求，服务器接收请求并进行处理，最终返回处理结果，通过数据链路传输到客户浏览器端进行画面渲染展示。

在B/S架构中，系统由以下三个部分组成，分别是浏览器、服务器和数据库。浏览器负责界面的展示和交互，服务器负责处理系统中的业务逻辑以及数据操作，数据库负责存储系统产生的数据。浏览器和服务器通过HTTP或HTTPS协议进行和服务器的通信，从而实现数据的传输与交互。

B/S架构拥有着简单部署方便维护的特性，因此。被广泛应用于各种web系统的设计和使用，例如电商平台、企业后台管理系统以及各种在线服务。在现代web开发中通常会使用前后端分离的B/S架构系统。

#### Vue.js框架

Vue框架是一门基于Javascript和HTML创建的用户界面的渐进式前端框架，由开发者尤雨溪最初设计实现并开源发布。 View框架的核心思想是组件设计和数据驱动视图，适合用于构建单页面应用的web应用界面层。其数据双向绑定的设计，使得界面能够根据数据的变化而实时的更新，大大减少了开发者直接对Dom元素的繁琐操作。

在技术实现上。 View是通过响应式数据和虚拟Dom的技术来实现双数据双向绑定。当数据发生变化时，view会监听数据并且实时的修改页面中需要变化的元素，而不会重新渲染整个页面，由此大大提升了系统的响应速度和性能。此外，Vue还有非常完善的生态体系。它支持一系列开发所需要的依赖如VueRouter用于实现路由功能，还支持用于状态管理的Pinia和Vuex等工具。同时它还拥有各种基于Vue开发的UI界面框架如ElementPlus，使其成为了一个能够支撑企业大型web应用的开发框架。

#### Java语言

Java是一门以面向对象为设计范式的编程高级语言，在国内互联网开发中占据了极高的地位。在JetBrains公司2020年一份报告中指出，中国有51％的程序员在使用Java，这个比例全球最高。在国内众多大厂如阿里巴巴、腾讯等大型互联网公司中，Java是不可或缺的核心技术栈。

Java最重要的设计理念之一便是“一次编写，随处运行”。Java通过在不同平台上的Java虚拟机的方式，来实现这一设计。在Java程序编写完成后，编译器会将其编译为字节码，在不同的系统上有相同的Java虚拟机实现，而Java虚拟机便会加载该字节码，以此实现一次编译到处运行的效果。 Java虚拟机的实现，使得Java程序有非常好的跨平台兼容性。使得Java程序在我们常用的系统，如Linux，Windows上都可以很好的运行。我们的系统的部署难度大大降低。

Java是一门面向对象的编程语言。面向对象的设计范式使得Java程序有非常好的兼容性、扩展性和可维护性，同时可以保证系统的健壮性。面向对象的核心理念为将事物全部抽象为对象的概念，通过构建对象之间的交互来完成系统功能的实现。相比较于过往的面向过程编程范式。面向对象注重的是对现实问题中的情况建模，使得我们的程序有更加清晰的结构，并且保证其易于维护和易于扩展。在我们的菜谱分享系统中，面向对象的编程范式非常有利于我们系统的构建。我们可以将系统中的用户、菜谱等抽象为一个对象，并设计其内部的行为和属性。我们只需要处理对象与对象之间的交互，便可以简单快速地构建起整个项目。

在企业级应用的开发中，Java是一门拥有成熟技术生态的语言。在Java生态中，以spring，spring boot等框架为代表的一系列开源框架，能够帮助我们开发者快速地简单地构建一个清晰的结构，扩展性强的后端运行系统。同时Java在企业系统、大数据处理以及分布式架构等各个方面都有广泛的应用，是当今最主流的服务器端开发语言。

#### Spring

Spring框架是一个开源的轻量级Java企业级应用的开发框架。 Spring的设计目的是简化Java企业级应用的开发，通过一系列完整的底层设计支持，使得开发者能够关注于业务逻辑的实现，不需要再过多的关心对象管理和底层技术。同时，它还拥有极其丰富的业务生态。如今，spring已成为Java企业级开发中必不可少的框架之一。

Spring框架是一个容器框架，它的核心思想包括了控制反转（IoC）和面向切面编程（AOP）。 Spring容器最主要的作用是托管Java程序中的各种Bean对象，最大程度地降低对象与对象之间的依赖与耦合，对象的创建和管理由Spring容器负责，对象只管使用，降低了系统的耦合度，也减少了程序员开发中需要考虑的问题，提高了开发的效率。实现该效果。是通过控制反转（IoC）的设计思想。所谓控制反转，就是将原本由对象创建对象的方式转为由spring容器创建对象，并通过依赖注入（DI）注入到所需要的对象中，对象和对象之间不再相互纠缠，在大型项目中，依赖关系的降低尤为显著。

面向切面编程（AOP），它的主要作用是将一些主要业务。以外的。系统功能剥离开来，通过切面的方式，在运行过程中动态地植入一些其他业务逻辑，如。记录日志管理事务权限校验。健全等功能。提高代码的模块化程度和维护性。

同时，spring框架还是一个粘合框架，借助spring框架简单的配置管理功能，可以将Java生态中的各种。中间件。解决框架，整合进来。轻松地构建起一个依赖众多的项目。

综上，Spring框架是当前Java后端开发最优的框架选择，无论是对于大型复杂项目还是对于中小型的简单项目，spring框架都能很好的胜任。因此我们选择了spring框架来构建菜谱分享网站的后端业务。

#### SpringBoot

SpringBoot是基于Spring框架创建的一个快速开发工具包，它的目的在于简化Spring框架和Java EE项目的配置、开发和部署工作。它通过约定大于配置的思想，减少了开发过程中的配置工作，使开发者和程序员能够快速便捷地构建和运行Java应用程序。

SpringBoot内置了Tomcat web服务器，使得它无需部署到传统的服务器应用中，可以独立作为一个Java程序直接运行。这种设计极大地方便了应用的部署。提高了我们系统开发测试和维护运行的效率。

由于它配置简单。开发效率高以及时spring生态的优势。spring boot已经成为现代。 Java互联网开发的常用框架，并且被广泛的应用于各种中小型项目以及微服务架构的项目中的开发使用。

#### SpringMVC

SpringMVC是Spring框架针对MVC架构设计模式开发的解决方案，因为其简单便捷的开发流程，在Java企业级开发中广受好评。在MVC架构中，我们将应用程序划分为模型层（Model）、视图层（View）、控制器层（Controller）。模型层对应着数据库和数据表。用于存储系统中的数据。控制器层对应传统JavaWeb中的Servlet，负责业务逻辑的处理。视图层即浏览器的展示层，用于系统的界面和数据的展示。 SpringMVC也继承此设计思想，其设计实现了一个前端控制器，用于接收HTTP请求，并匹配对应的控制器来进行业务处理。

Spring mvc的结构清晰，扩展性和灵活性高，与spring生态的一系列框架高度集成。在现代Java后端项目开发中，SpringMVC常常配合Restful风格，通过JSON数据交互来实现前后端分离的应用架构。

#### MyBatis-Plus

MyBatis是一个优秀的半ORM持久层框架，用于替代传统的JDBC来实现Java程序与关系型数据库的交互。他通过XML文件的配置方式，将SQL语句的编写和Java代码解耦，解决了传统JDBC带来的SQL语句修改维护困难的问题。并且XML编写SQL语句的功能强大。自带SQL语句注入问题的解决方案，使得MyBatis成为了当今最主流的持久层框架。

MyBatis-Plus是基于MyBatis框架开发的一个增强插件。它的设计目标是简化数据库操作层的开发，它封装了一些非常常用的数据库操作如基础的增删改查及常用的分页查询等，并且它没有改变MyBatis原有的功能，将原本的半ORM框架，转变成了一个全ORM框架的开发体验。

在实际开发项目中，my Baptiste常常与spring生态的一系列框架结合，成为Java项目中最常见的开发框架组合。

由于其开源免费性能稳定和生态完善等优势。 MySQL在web开发中得到了非常广泛的应用。它常常与spring框架MyBatis框架等结合使用，是中小型项目开发乃至大型项目的构建中最优的选择之一。

#### 登录接口

登录接口主要用于完成用户登录权限校验功能，是系统安全和权限控制的重要部分。本系统使用JWT实现用户登录功能，接口通过RESTful风格实现前后端数据交互。当用户在前端输入用户名密码并点击登录提交后，系统通过此登录接口对用户信息进行校验。

系统提供 {{BaseUrl}}/user/login 作为登录接口地址，采用HTTP POST请求方法接收用户提交的账号密码信息。请求参数包括用户名、密码两个字段，前端通过JSON格式将数据传递给后端接口。

> 登录接口流程图

当服务器接到登录请求后，请求首先进入控制层（Controller），控制层对参数进行基本的数据校验，然后调用业务层（Service）执行登录校验相关业务逻辑。业务层首先通过用户账号调用数据访问层（Dao）查询用户信息，若查询用户为空则返回登录失败；若查询成功，则进入下一步。将用户输入的密码和查询结果做比对，若用户密码不匹配返回登录失败密码，若匹配则进入下一步。当用户输入密码正确。代表着该用户登录成功。系统会为其生成一份专属登录令牌（Token），在每次请求中提交该Token则可以验证用户登录信息。登录接口会将此token作为请求响应返回给前端，用户获取到Token则代表登录成功。

通过上述的设计实现，系统登录接口能很好地完成用户身份校验的功能，并通过Token为后续系统的权限控制访问控制提供了坚实的基础。

#### 菜谱查询接口

菜谱查询接口主要用于用户或系统对菜谱的检索功能。菜谱查询分为分页查询、按ID查询、条件查询等，接口通过RESTful风格实现前后端数据交互，通过JSON格式向前端传输菜谱相关的数据。

以分页查询接口为例，系统提供 {{BaseUrl}}/recipe/page 作为分页查询菜谱接口地址，采用HTTP POST请求方法接收用户提交的分页查询信息。请求参数包括当前页、条目数量两个字段，前端通过JSON格式将数据传递给后端接口。

请求首先进入控制层（Controller），控制层对参数进行基本的数据校验，然后根据分页参数组装查询Wrapper，调用业务层（Service）和数据操作层（Dao）执行分页查询相关业务逻辑。查询结果为一个装载了菜谱信息的列表和分页数据的结果集。控制层将此结果集返回给前端完成本次接口的调用。

通过上述的设计实现，系统菜谱查询接口能够有效地完成菜谱查询的功能，为系统的菜谱展示等相关模块提供基础。

#### 菜谱新增、修改接口

菜谱新增接口主要用于用户新增、编辑菜谱的功能。接口通过RESTful风格实现前后端数据交互，通过JSON格式在前后端之间传输菜谱相关的数据。

以新增菜谱接口为例，系统提供 {{BaseUrl}}/recipe/add 作为新增菜谱接口地址，采用HTTP POST请求方法接收用户提交的分页查询信息。请求参数包括菜谱信息的一系列相关参数，前端通过JSON格式将数据传递给后端接口。

请求首先进入控制层（Controller），控制层对参数进行基本的数据校验，然后和相关用户信息进行组装，形成新增的菜谱对象，调用业务层（Service）和数据操作层（Dao）执行新增菜谱业务逻辑，将新菜谱的信息保存进数据库。若用户参数有误（如缺少必须的参数）则返回新增失败。

通过上述的设计实现，系统菜谱新增、修改接口能够有效地完成菜谱的编辑功能，为用户提供系统基本的菜谱分享功能的入口，是用户丰富网站内容的开端。

#### 个人信息查询接口

个人信息查询接口主要用于登录用户或系统查询个人相关的信息的接口，通过restful风格实现前后端数据交互，通过JSON格式在前后端之间传输用户相关的数据。

系统提供 {{BaseUrl}}/id/{id} 作为个人信息查询接口地址，采用HTTP GET请求方法接收用户提交的Id信息。请求参数包括用户的ID，前端通过路径参数将数据传递给后端接口。

请求首先进入控制层（Controller），控制层调用业务层（Service）和数据操作层（Dao）将ID作为参数查询用户信息，若查询成功，返回用户信息；若查询失败，返回失败信息。

通过上述的设计实现，完成了基本的用户信息查询，是用户基础功能和功能拓展的必备条件。
